# Сайт «Доверительная Бухгалтерия»

Сайт бухгалтерской компании ООО «Профит-консалт». Статика на GitHub Pages,
живёт на `blackredwhitee.github.io/buhstart-next`, деплой — пуш в `main`.

## Правила работы

- **Не пушить без явного разрешения.** Коммитить можно, `git push` — только когда попросили.
- **Ничего не «улучшать» по своей инициативе.** Дизайн и тексты меняются только по запросу.
- Отвечать коротко и по делу. Длинные структурированные ответы не нужны.
- После каждой правки страницы прогонять `dcedit.check()` — см. ниже.

## Устройство страниц: DC-бандлы

13 страниц — это выгрузка из конструктора Design Compiler. Обычного HTML в них нет,
править «как текст» нельзя. Внутри каждого файла:

| Блок | Что внутри |
|---|---|
| `<script type="__bundler/manifest">` | JSON: UUID → gzip+base64 ресурса (шапка, подвал, шрифты, React) |
| `<script type="__bundler/ext_resources">` | JSON: имя компонента → UUID в манифесте |
| `<script type="__bundler/template">` | **JSON-строка** со всей разметкой страницы |
| `<script type="text/x-dc">` внутри шаблона | класс `Component extends DCLogic` — состояние и обработчики |

Исключения: `calculator.html` и `calculator-public.html` — обычный HTML, правятся напрямую.

### Главная ловушка: safe_json

Внутри JSON-строки шаблона все `</` экранированы как `<\/`. Если экранирование
потерять, браузер закроет внешний `<script>` раньше времени и страница упадёт
с «Error unpacking: Unterminated string in JSON». Поэтому:

- `json.dumps(html, ensure_ascii=False)` — **обязательно** `ensure_ascii=False`, иначе
  кириллица превратится в `\uXXXX` и рантайм не разберёт;
- после `json.dumps` — `.replace('</', '<\\/')`.

Не делать это руками. Использовать `dcedit.py`.

### dcedit.py

Хелпер в корне репозитория. Читает и пишет шаблоны и блобы, перед записью проверяет,
что JSON снова парсится, и не даёт сохранить сломанный файл.

```python
import dcedit as D

D.read_template('index.html')                    # разметка страницы как строка
D.edit_template('index.html', (old, new), ...)   # замены с проверкой
D.write_template('index.html', html)             # запись целиком
D.read_blob('index.html', D.HEADERS['index.html'])   # шапка страницы
D.write_blob(path, uuid, html)                        # запись блоба
D.check('index.html')                            # контроль после правки
```

`D.HEADERS` — словарь «страница → UUID шапки».

### Блобы шапки и подвала — по копии на страницу

`SiteHeader` и `SiteFooter` у **каждой** страницы свои, с уникальным UUID.
Правка меню на главной не влияет на остальные 11 страниц — надо пройти по всем.
UUID шапок лежат в `dcedit.HEADERS`, UUID подвалов ищутся по наличию нужного
фрагмента в блобе.

### Порча манифеста

Уже случалась: при перезаписи блоба у записи `SiteHeader` потерялась закрывающая
скобка, и девять следующих записей — включая `SiteFooter`, шрифты и React — оказались
вложены внутрь неё. DC не находил их по UUID, грузил `SiteFooter.dc.html`, получал 404
и рисовал пустоту вместо подвала.

Проверка: у всех записей манифеста верхнего уровня ключи должны быть только
`mime`, `compressed`, `data`. Любой UUID внутри записи — порча.

## Внешние CSS

`fonts.css`, `anim.css`, `responsive.css` подключаются из блоба шапки и **перебивают**
стили в шаблонах, потому что идут позже. Меняя оформление, править и их — иначе
правка не сработает. Браузер их кэширует, при проверке нужен `Cmd+Shift+R`.

## Особенности DC-рантайма

- **Вложенный `sc-if` не разворачивается.** Условный блок внутри другого `sc-if`
  не отрисуется. Вместо него — управление через `display:{{ someShow }}`.
- **Программная подстановка значений в поля не доходит до состояния.** DC перерисовывает
  input из состояния, поэтому `el.value = x` + `dispatchEvent` не работает. Формы
  тестировать настоящими кликами и вводом.
- Обработчики привязываются как `sc-camel-on-click="{{ handler }}"`,
  значения — `value="{{ field }}"`, списки — `<sc-for list="{{ items }}" as="i">`.

## Формы

Все формы отправляют заявку в Google Apps Script, тот же адрес, что у калькулятора.
В компоненте страницы есть метод `send(payload)`.

Скрипт различает заявки по полю `type`, значения строго: `lead`, `calculator`, `vacancy`.
Любое другое падает в лист «Заявки».

| Лист | Поля, которые читает скрипт |
|---|---|
| Заявки | `name`, `phone`, `email`, `comment` |
| Калькулятор | `name`, `company`, `phone`, `email`, `tariff`, `employees`, `system`, `kpBase64`/`kpName`/`kpMime` |
| Работа у нас | `name`, `phone`, `contact`, `role`, `exp`, `skills`, `about`, `resumeBase64`/`resumeName`/`resumeMime` |

Источник заявки пишется в `comment`, отдельной колонки под него нет.
Запрос идёт в `mode: 'no-cors'` — ответ прочитать нельзя, форма покажет «Отправлено»
даже при ошибке. Проверять только по самой таблице.

Во всех формах обязательная галка согласия на обработку персональных данных:
без неё отправка блокируется.

## Дизайн-система

Стиль — «бенто»: серая подложка, белые плитки с крупными скруглениями без рамок,
тёмная и оранжевая плитки как акценты.

```
Подложка страницы   #F4F4F5
Плитки              #FFFFFF, border-radius 26px, без border
Тёмная плитка       #18181B
Оранжевая плитка    #F07828   (наведение #E56800)
Метка-пилюля        фон #FFEDD9, текст #B4530F, radius 16px
Кнопки              radius 16px, высота 54px
Текст основной      #18181B
Текст второстепенный #52525B
Текст приглушённый  #71717A
Разделители         #E4E4E7
Успех               #2D7A4F      Ошибка #C4453A
```

Правила:
- **Пастельных оттенков нет.** Оранжевый — только полной насыщенности.
- **Серые — чистые нейтральные, без бежевого подтона.** Тёпло-серые читаются как грязь.
- Шрифт **Onest**, файлы `uploads/Onest-*.woff2`, подключение в `fonts.css`.
  Максимальный вес 800, `font-weight:900` не использовать.
- Иллюстрации — плоский SVG в `uploads/`: оранжевый, нейтральный серый, тёмный, белый.
  Пастель и тени не использовать. Вес файла порядка 1–2 КБ.

Анимации уже есть и их достаточно: появление блоков при прокрутке (`data-rv`,
`data-wipe`), наклон кликабельных карточек (`data-tilt`), параллакс пятен, бегущая
строка, счётчики. Всё отключается при `prefers-reduced-motion`. Добавлять новое
движение не нужно — сайт станет суетливым.

**Движение только на кликабельных элементах.** Наклон и подсветка на обычном `div`
провоцируют клик — клиент на это жаловался.

## Проверка

Локальный сервер: `python3 -m http.server 8899` из корня репозитория.

После правок:

```bash
python3 -c "
import dcedit as D, glob
for f in sorted(glob.glob('*.html')):
    if not f.endswith('.dc.html') and not f.startswith('_'): D.check(f)
print('валидно')"
```

Дополнительно смотреть в браузере: нет битых картинок, отрисовался подвал,
нет горизонтальной прокрутки, в консоли нет ошибок DC.

Файлы `*.dc.html` — исходники конструктора, не трогать. Файлы с `_` в начале имени —
временные, в репозиторий не коммитить.
